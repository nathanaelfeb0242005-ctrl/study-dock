03 / The problem

A language model is not a live library.

It can lack a new course handbook, a private policy, or a specialized reference.

Without retrieval

“I think the deadline is Friday.”

Sounds confident, but the model may not know the current document.

With retrieval

“Here is the handbook section.”

Search the document first, then answer using what it actually says.

Hypothetical example · Wiki: problem · Sources: S01, S03

04 / Core idea

RAG = open-book answering

Retrieval-Augmented Generation: an AI model uses relevant outside information as additional context before responding.

Analogy: The model is a student; the knowledge base is a textbook; retrieval finds the right page.

Wiki: intro · Sources: S01, S02, S03

07 / Retrieval

Two ways to find an answer

Keyword

Match the words

Query: “document chunks” → search for those terms.

Semantic

Match the meaning

Query: “small pieces of text” → may find “document chunks.”

Our browser Wiki uses simple keyword matching. Actual semantic search generally requires embeddings or other retrieval infrastructure.

09 / Quality

A citation is not automatically proof.

Check the source

Does it say that?

Open the original document and compare the specific statement.

Check the match

Is it the right passage?

An unrelated citation can make a wrong answer look authoritative.

10 / Workflow design

Two checks. Two feedback loops.

Collect→Validate→Wiki→Slides→Test
Loop A: upstream

Bad evidence?

Return to the source note before writing slides.

Loop B: downstream

Bad explanation?

Return to outline or slide draft, then test again.
